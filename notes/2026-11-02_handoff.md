## What was corrected tonight, and where it is recorded

- **A code slip in the dim-reg tadpole, caught by a failed prediction.** The first plain-measure run gave K₀[dim reg] = −1/8 against
  the predicted −3/8 (the covariant run beside it gave −3/8). An exact-in-n evaluation of the p⁰ order by hand agreed with the
  code's bubble and not its tadpole: the seagull symbol is built from the 4-dimensional x-space expansion and its flat trace term
  lacked the k_⊥² of the n − 4 extra loop-momentum components, which has no pole and feeds the finite part. With DeWitt's measure
  that coefficient is (g^{−1/4}√g g^{−1/4})⁽²⁾ = 0, which is why the covariant run was right by itself. Fixed
  (`ud1962_lib.perp_symbol`, `tadpole_dimreg_full`); the prediction was not changed; the first log is in
  `results/superseded/rung1_massive_plain_sandbox_4d_tadpole_symbol.log`; recorded in the script header ("RECORD OF THE FIRST
  RUN"), results note §9, and as a rule in the ledger: in dim reg, anything built from a 4-dimensional expansion is exact for the
  pole and wrong for the finite part — third instance in two days (1 Nov: angular averages, dot products; 2 Nov: the symbol).
  Nothing earlier is affected (the massless p⁴ part is bubble-only; `rung1_dimreg.py` reports the pole only).
